# 第六阶段设计：财务功能拓展（账簿结账 / 工资深化 / 报表同期）

- 日期：2026-08-22
- 状态：已与用户确认
- 前置：第三阶段（月结/付款批次/银行流水/预算）、第四阶段（安全配置）、第五阶段（科目表/自动凭证/三大报表）已交付

## 1. 目标与定位

在五阶段交付的会计核算底座上，补全出纳日常最常用的三块能力：

1. **账簿与结账闭环**：科目余额表（试算平衡）+ 年末损益结转凭证
2. **工资场景深化**：社保公积金台账（含单位部分与年度调基）、个税累计预扣法、工资条打印
3. **报表增强**：三大报表上年同期对比列

定位不变：本地单机轻量工具，不扩展成完整 ERP。

### 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 账簿范围 | 仅科目余额表；总账、明细账不做 |
| 结转时机 | 仅 12 月月结时自动结转（3103 本年利润 → 3104 未分配利润），1-11 月利润表继续实时汇总 |
| 结转凭证口径 | 三大报表汇总排除 `period_close` 分录（报表口径完全不变）；科目余额表包含全部凭证（真实账面） |
| 社保费率粒度 | 4 个合计费率（单位社保/个人社保/单位公积金/个人公积金），不分险种 |
| 基数上下限 | 支持 clamp（全局配置上下限，调基与计算时截断） |
| 单位部分 | 计入台账、计入工资结果（新列）、联动工资计提凭证（全额成本口径+代扣腿） |
| 个税算法 | 改为法定累计预扣法；历史已存月份视为"已预扣"，从任意月启用自然平滑，无数据迁移 |
| 工资条 | 前端打印 CSS（浏览器另存 PDF），零新增 PDF 依赖；需敏感数据解锁状态 |
| 同期对比 | 三大报表各加一列；无上年数据显示 `-` 不报错；科目余额表不加 |

### 2.2 `salary_results` 新列（批次 2a）

`social_security_employer REAL DEFAULT 0`、`housing_fund_employer REAL DEFAULT 0`。历史行为 0，不回填。

`scope TEXT DEFAULT 'monthly'`（`monthly` / `cumulative`）。预置累计预扣率表 7 档（3%~45%，速算扣除 0~181920）随迁移 `INSERT OR IGNORE`。现有月度表保留不删。

`ss_base_min` / `ss_base_max` / `hf_base_min` / `hf_base_max`，0 表示不限制。

## 3. 批次一：科目余额表 + 年末结转

### 3.1 科目余额表

- 命令 `get_trial_balance(from_month, to_month)`：每科目输出期初余额（借/贷）、本期发生额（借/贷）、期末余额（借/贷）。
  - 期初 = 启用月之前期初余额 + 区间前凭证累计；本期发生 = 区间内全部 active 凭证分录（含 `period_close`）；期末 = 期初 + 本期净发生。
  - 仅返回有发生或有余额的科目 + 资产负债权益类科目。
  - 借贷合计不平衡时（理论上不会）返回标记，前端红色提示。
- 导出 `export_trial_balance_excel`（rust_xlsxwriter，与三报表同风格）。
- 前端：并入"财务报表"页第 4 个 Tab，不新增菜单项。

### 3.2 年末结转凭证

- 触发：12 月执行正式月结时，月结流程内自动生成两张凭证（任一失败则月结失败）：
  1. 各损益类科目余额 → 3103 本年利润（每科目一行分录，借贷方向按科目 direction）
  2. 3103 余额 → 3104 利润分配—未分配利润
- `source_type='period_close'`，`source_id` = 年份月份数字（如 202612），天然受 `(source_type, source_id) WHERE status='active'` 唯一索引防重；损益净额为零时跳过。
- 反月结：同事务作废该月 `period_close` 凭证（复用 void 联动模式）。
- 报表口径：`build_balance_sheet` / 利润表 / 现金流量表的余额与发生额汇总 SQL 统一加 `AND source_type != 'period_close'`；3104 行继续用"期初 + 利润表净利润滚入"口径（与含结转凭证的实际余额数学一致）。
- 月结工作台：12 月显示"年末结转"检查项。

## 4. 批次二：工资场景深化

### 4.1 2a 社保台账与凭证联动

**工资计算挂接**（salary.rs）：

- 按 `salary_month` 年份匹配台账；命中则用台账基数与费率，并 clamp 到上下限。
- 未命中回退现状：`employees.social_security_base` / `housing_fund_base` + `SalaryRule` 个人费率（单位部分 = 0）。历史行为完全兼容。
- 单位部分计算结果写入 `salary_results` 新列。

**计提凭证升级**（仅新生成凭证生效，历史凭证不重算）：

- 计提（按人头，沿用现有生成时机）：
  - 借 部门映射科目（默认 6602）：`gross - attendance - other + 单位社保 + 单位公积金`
  - 贷 2211：同额
- 新增代扣腿（与计提同凭证生成）：
  - 借 2211：`个人社保 + 个人公积金 + 个税`
  - 贷 2241 其他应付款：`个人社保 + 个人公积金`；贷 2221 应交税费：`个税`
- 效果：2211 贷方 = 应发净额 + 单位部分；借方 = 代发 net + 代扣个人部分，余额为单位部分挂账。社保缴纳、个税解缴的银行支出由用户经银行流水"生成凭证"冲销：缴费借 2211（单位）+ 2241（个人），缴税借 2221（现有能力，无新开发）。
- 代发凭证（salary_payment）不变。

**调基向导**：社保台账页"新年度调基"弹窗——复制上年度台账 → 套用新基数（统一系数或手工逐行）→ clamp 上下限 → 保存为新年度。

**前端**：工资管理菜单组新增"社保台账"页（年度切换、逐行编辑、调基向导、上下限设置入口）。

### 4.2 2b 个税累计预扣法

**算法**（替换 calculate_tax 的工资调用路径）：

```
累计应纳税所得额 = Σ(gross) - Σ(社保个人+公积金个人) - 5000×月数 - Σ(special_deduction)
当月应预扣 = max(0, 累计应纳税所得额×预扣率 - 速算扣除 - 累计已预扣)
```

- Σ 取该员工当年已保存非 void `salary_results`（含当月）；月数 = 记录月数。
- 累计已预扣 = 当月之前各月 `tax_amount` 之和。历史按月算法的记录自然作为基数，启用当月即平滑（多退少补体现在后续月份）。
- 已锁定/月结月份不重算（沿用 locked guard）。
- 税率表：`tax_rules` 中 `scope='cumulative'` 的 7 档。

**年度汇总表**：命令 `get_annual_tax_summary(year)` 输出每人：累计收入、累计减除费用、累计专项扣除、累计专项附加扣除、累计应纳税所得额、已预扣、年度应预扣、差额；`export_annual_tax_summary_excel` 导出。入口：工资核算页"个税年度汇总"弹窗。

### 4.3 2c 工资条打印

- 工资核算页"工资条"按钮 → 弹窗预览：选定月份（默认当前核算月）、员工范围（默认全部非 void），每人一张卡片式工资条（项目/金额两列表格 + 实发合计加粗）。
- 生成前置检查：敏感数据须处于解锁状态，未解锁提示引导解锁（复用 5min 全局解锁）。
- 打印：`@media print` 隐藏应用框架、每卡片 `page-break-after`，用户浏览器"打印 → 另存 PDF"。
- 金额在工资条中显示明文（发放核对用途）。

## 5. 批次三：三大报表上年同期对比

- `build_balance_sheet`：加"上年年末数"列（时点数：上年 12 月口径）。
- 利润表/现金流量表：加"上年同期累计"列（期间数：上年 1 月 ~ 上年同月，排除 `period_close`）。

- 无上年数据（库中无该期间凭证）：列值置 null，前端显示 `-`。
- 前端财务报表页三个 Tab 各加一列；三张 Excel 导出同步加列。

## 7. 错误处理

- 年末结转生成失败：月结整体失败并回滚，中文报错（凭证号冲突/损益科目停用等场景）。
- 台账保存：`employee_no + profile_year` 冲突报"该员工该年度已有台账"；费率范围校验 0~1。
- 调基向导：目标年度已存在台账时拒绝覆盖，提示先删除或逐行编辑。
- 工资条：月份无数据、未解锁均给中文提示。
- 个税：无 `cumulative` 档命中（所得额超最高档上限 max=NULL 兜底）按最高档。

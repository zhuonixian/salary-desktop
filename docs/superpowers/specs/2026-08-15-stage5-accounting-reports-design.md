# 第五阶段设计：财务专业功能（科目表与三大报表）

- 日期：2026-08-15
- 状态：已与用户确认
- 前置：第三阶段（月结/付款批次/银行流水/预算）、第四阶段（安全配置）已交付

## 1. 目标与定位

为出纳本地工资核算工具增加财务专业能力：

- 预置《小企业会计准则》全套一级科目的**科目表**
- 业务数据自动派生**记账凭证**（复式记账，借贷平衡）
- 基于凭证生成**资产负债表、利润表、现金流量表**
- 报表支持导出 Excel

定位不变：本地单机轻量工具，**不做手工记账凭证入口**，不扩展成完整 ERP。

### 已确认的关键决策

| 决策点 | 结论 |
|---|---|
| 报表数据来源 | 自动派生：业务事件按映射规则自动生成凭证，无手工记账 |
| 科目预置 | 全套《小企业会计准则》一级科目约 70 个，可停用，可新增自定义科目 |
| 期初余额 | 用户选定启用月逐科目录入，保存时校验"资产=负债+权益" |
| 凭证覆盖业务 | 工资计提与代发、报销计提与付款、发票费用入账、银行流水入账（四项全选） |
| 记账期间 | 月结即关账：正式月结校验并冻结凭证，反月结后重算 |
| 架构方案 | 方案 A：凭证落库（事件驱动物化凭证），报表实时汇总 |

## 2. 数据模型（新增 5 张表）

### 2.1 `gl_accounts` 科目表

| 字段 | 说明 |
|---|---|
| `code` TEXT PK | 科目编码，如 `1001` 库存现金、`1002` 银行存款、`2211` 应付职工薪酬、`2241` 其他应付款、`4103` 本年利润、`4104` 利润分配、`6602` 管理费用 |
| `name` TEXT | 科目名称 |
| `category` TEXT | asset / liability / equity / cost / profit_loss |
| `direction` TEXT | debit / credit（余额方向） |
| `cash_flow_category` TEXT | operating / investing / financing / none（现金流量表分类，按对方科目归类用） |
| `is_system` INTEGER | 预置科目 =1，不可删除 |
| `is_active` INTEGER | 停用后不再出现在映射选择中，已有凭证不受影响 |
| `remark`、`created_at`、`updated_at` | 常规字段 |

预置科目随 DB 初始化/迁移插入（`INSERT OR IGNORE`），现金、银行类科目 cash_flow_category 置 none，本身不参与分类（由对方科目决定）。

### 2.2 `vouchers` 记账凭证

| 字段 | 说明 |
|---|---|
| `id` INTEGER PK | |
| `voucher_no` TEXT UNIQUE | 按月连续编号 `记-YYYYMM-NNN` |
| `voucher_date` TEXT | 凭证日期（取业务发生日期） |
| `belong_month` TEXT | 所属月份 |
| `source_type` TEXT | salary_accrual / salary_payment / reimbursement_accrual / reimbursement_payment / invoice_expense / bank_manual |
| `source_id` INTEGER | 源业务单据 id（bank_manual 为 bank_transactions.id） |
| `total_amount` REAL | 借贷合计（单边） |
| `status` TEXT | active / void |
| `remark`、`created_at`、`updated_at` | |

约束：部分唯一索引 `(source_type, source_id) WHERE status='active'`，防止同一业务重复生成凭证。

### 2.3 `voucher_lines` 凭证分录

| 字段 | 说明 |
|---|---|
| `id` INTEGER PK | |
| `voucher_id` INTEGER FK→vouchers | ON DELETE CASCADE |
| `account_code` TEXT FK→gl_accounts | |
| `debit_amount` REAL DEFAULT 0 | 借方金额 |
| `credit_amount` REAL DEFAULT 0 | 贷方金额 |
| `summary` TEXT | 摘要，如"2026-08 工资计提" |
| `line_order` INTEGER | 行序 |

生成时强制校验：`Σ debit = Σ credit` 且两者 > 0。

### 2.4 `opening_balances` 期初余额

| 字段 | 说明 |
|---|---|
| `month` TEXT | 启用月份。全库只允许一个启用月：由 `app_settings` 记录 `accounting_start_month`，所有期初行必须同月，应用层校验 |
| `account_code` TEXT FK→gl_accounts | |
| `debit_amount` / `credit_amount` REAL | 余额按科目方向填入对应侧 |

保存校验：借方合计 = 贷方合计（即 资产 = 负债 + 权益），不平则拒绝保存并返回各侧差额。启用月之后月份的报表 = 期初 + 凭证累计；启用月之前的月份报表全为 0 并提示"未启用"。

### 2.5 `account_mappings` 业务维度→科目映射（泛化）

> 实现说明：原设计为 `expense_account_mappings`（仅费用类型单维度）；实现时泛化为 `account_mappings(scope, key)` 二元维度表，同一张表承载"费用类型→科目"与"部门→科目"两类映射，避免后续每加一个映射维度就建一张表。

| 字段 | 说明 |
|---|---|
| `scope` TEXT | 映射维度：`expense_type`（费用类型）/ `department`（部门） |
| `key` TEXT | 维度值：scope=expense_type 时对应 `invoice_expense_types.code`；scope=department 时对应员工 `department` 名称 |
| `account_code` TEXT FK→gl_accounts | 费用类型映射必须是 profit_loss/cost 类科目 |

`(scope, key)` 唯一。未配置映射的费用类型回退默认 `6602 管理费用`；未配置映射的部门同样回退 `6602`（见 3.1 规则 1）。

## 3. 凭证自动生成规则

### 3.1 六类业务事件

| # | 触发时机 | 凭证内容 |
|---|---|---|
| 1 | 工资结果锁定（每批/每人） | 借 费用类科目（按员工部门映射，默认 6602 管理费用）＝应发−缺勤扣款−其他扣款；贷 2211 应付职工薪酬＝同额。个人社保/公积金/个税**保留 2211 贷方余额**（实现精化：原设计转账到 2241，改为不动，避免与付款凭证口径脱节），实际缴纳时由银行流水手工凭证 借 2211 / 贷 1002 冲减。缺勤扣款/其他扣款属当期未发生费用，直接少计费用与负债，不冲减已计提金额 |
| 2 | 工资付款批次标记已付款 | 借 2211 应付职工薪酬＝批次实发合计；贷 1002 银行存款 |
| 3 | 报销单审批通过 | 借 费用类科目（按其发票费用类型逐张映射，无类型默认 6602）；贷 2241 其他应付款—报销＝报销总额 |
| 4 | 报销付款批次标记已付款 | 借 2241 其他应付款—报销＝批次合计；贷 1002 银行存款 |
| 5 | 未关联报销单的发票登记（按 belong_month） | 借 费用类（按发票费用类型映射）；贷 2241 其他应付款 |
| 6 | 银行流水（未匹配）人工指定科目 | 用户在弹窗选择对方科目：支出流水选借方科目（贷方固定 1002），收入流水选贷方科目（借方固定 1002）。如手续费：借 6603 财务费用，贷 1002；利息收入：借 1002，贷 6603 |

### 3.2 防重复计费口径

- **发票只入一次账**：已挂报销单的发票随报销审批入账（规则 3），不再生成规则 5 凭证；判断标准为 `reimbursement_claim_invoices` 是否存在关联
- **已匹配银行流水不生成凭证**：其对应付款凭证已由付款批次生成（规则 2/4），避免银行存款重复冲减；规则 6 仅面向 `status='unmatched'` 且未忽略的流水
- **已入账流水禁止匹配付款批次**（实现补充）：已存在 active `bank_manual` 凭证的流水，人工确认匹配（confirm）与自动匹配（auto_match）均拒绝/排除，否则同一笔银行存款会被 bank_manual 凭证与付款批次凭证双重冲减
- 发票从报销单移除后，若满足规则 5 条件则补生成单独入账凭证

### 3.3 作废与重算联动

沿用付款批次"作废释放来源"模式，源单据变更时在同一事务内同步凭证：

| 源操作 | 凭证联动 |
|---|---|
| 工资结果解锁 | 对应 salary_accrual 凭证置 void |
| 付款批次作废 | 对应 payment 凭证置 void |
| 报销单反审批/作废 | 对应 reimbursement_accrual 凭证置 void |
| 发票作废 | 对应 invoice_expense 凭证置 void |
| 源单据重新满足条件（如重新锁定） | 重新生成新凭证（旧凭证已 void，新凭证继续编号） |
| 银行流水取消匹配/忽略 | bank_manual 凭证置 void |

### 3.4 月结冻结

- 已正式月结月份：所有源业务命令本就被锁账，凭证随之冻结；直接修改凭证的命令一律拒绝已月结月份
- 正式月结新增检查项"**记账凭证平衡**"：存在借贷不平衡或合计为 0 的 active 凭证时阻塞月结
- 反月结后源数据可改，凭证按上述联动规则重算

## 4. 报表生成

后端新增模块 `src-tauri/src/accounting.rs`。凭证已物化，报表查询时实时汇总（单机出纳月凭证量数百条，无性能压力），不建快照/汇总表。

### 4.1 科目余额（内部基础）

```
期末余额 = 期初余额（若月份 >= 启用月）± 启用月以来全部 active 凭证借贷发生额（按科目 direction 取正负）
本期发生额 = 当月 active 凭证借贷合计
```

### 4.2 资产负债表（期末时点数）

- asset 类科目期末余额 → 资产各行（货币资金 = 现金+银行类科目合计）
- liability / equity 类 → 负债和权益各行
- **未分配利润** = 期初录入的未分配利润科目余额 + 启用月以来累计净利润（净利润来自利润表逻辑，两表自动衔接）
- 表尾兜底校验：资产合计 = 负债和权益合计；不平衡时前端红字提示（自动凭证理论恒平衡，此为兜底）
- 展示"期末余额 / 年初余额"两列（年初 = 启用月期初口径）

### 4.3 利润表（期间发生数）

- profit_loss 类科目当月发生额 + 本年累计发生额
- 标准表式：营业收入、营业成本、税金及附加、销售费用、管理费用、财务费用、营业利润、利润总额、净利润
- 自动派生模式下营业外收支、所得税费用等行恒为 0，**显示 0 不隐藏**，保持表式完整
- 无上年数据时"上年金额"列显示 0

### 4.4 现金流量表（直接法）

- 扫描当月所有涉及现金等价物科目（1001 库存现金、1002 银行存款）的凭证
- 每笔现金流动按其**对方分录科目**的 `cash_flow_category` 归类：经营/投资/筹资活动现金流入流出
- 对方科目 category 为 none 的金额归入"其他"行，并在页面列出未归类明细，引导用户到科目表补分类
- 标准表式：一、经营活动现金流量（销售商品收到的现金为 0 等行保留）；二、投资活动；三、筹资活动；四、现金净增加额

### 4.5 Excel 导出

- 三大报表各自导出 xlsx（复用 rust_xlsxwriter，与月结包导出同模式）
- 文件名：`资产负债表_YYYYMM.xlsx` 等，保存路径沿用现有导出对话框约定

## 6. 错误处理

- 凭证生成与源业务状态变更放**同一事务**，任一步失败整体回滚
- 中文错误提示：期初余额不平衡（含差额）、科目被凭证引用时停用/删除、已月结月份修改凭证、流水已匹配时生成 bank_manual 凭证、映射科目非损益类等

## 8. 范围外（明确不做）

- 手工记账凭证（收/付/转凭证录入）
- 多级明细科目（只做一级科目）
- 期末结转损益凭证（利润表直接从损益科目发生额计算，无需结转）
- 上年同期对比数据（无历史账）
- 凭证打印、账簿打印

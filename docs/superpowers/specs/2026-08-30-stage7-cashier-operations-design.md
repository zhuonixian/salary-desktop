# 第七阶段设计：出纳运营闭环（资金账户 / 通用收付款 / 对账 / 审批留痕）

- 日期：2026-08-30
- 状态：已与用户确认方向，待按批次实施
- 前置：第三至第六阶段主线已交付；第六阶段 Windows exe 手工验收作为本阶段 Gate 0

## 1. 目标与定位

第七阶段将现有“工资、报销、付款批次、银行流水、自动凭证、月结”能力扩展为可长期使用的本地出纳运营闭环：

1. 建立银行、现金、第三方支付账户主数据，并在凭证分录上增加资金账户辅助核算。
2. 支持员工之外的供应商及其他往来单位，补齐通用收款、付款、内部转账。
3. 将单据状态改为命令驱动的追加式流程，记录提交、审批、驳回、结算、冲正全过程。
4. 将银行流水从“一笔流水对应一个付款批次”升级为“银行流水与账面资金分录多对多核销”。
5. 增加现金/银行日记账、银行余额调节表、员工借款与备用金核销。
6. 将全局月份真正贯通页面，并让普通业务日志记录当前操作人。

产品边界不变：面向单公司、本地单机、出纳主导的轻量财务工具，不宣称替代法定财务软件，不在本期引入云端、多用户账号权限或在线审批。

## 2. 关键设计决策

| 决策点 | 结论 |
|---|---|
| 资金账载体 | 账面日记账从 `voucher_lines` 实时派生，不再复制一张可编辑日记账表 |
| 账户辅助核算 | `voucher_lines` 增加可空 `fund_account_id`；每条现金/银行分录必须标记具体资金账户 |
| 对账目标 | 银行流水与账面资金分录核销，不再只匹配付款批次 |
| 对账关系 | 使用 allocation 表支持一对一、一对多、多对一；金额累计不得超出任一侧可核销余额 |
| 通用业务单 | 使用统一 `fund_documents`，通过 `document_type` 区分收款、付款、内部转账、员工借款、借款核销 |
| 状态修改 | 前端不得直接编辑状态；仅允许调用 submit/approve/reject/settle/void/reverse 命令 |
| 已结算纠错 | 已结算单据不删除、不直接作废；在开放月份创建相反方向冲正单和冲正凭证 |
| 操作人 | 新增本地操作人档案与当前操作人会话，用于署名和审计；不等同于强身份认证 |
| 经办复核 | 可选 `maker_checker_enabled`；启用时提交人与审批人不得相同。单机切换身份仍属于流程约束，不宣称安全隔离 |
| 付款批次 | 保留现有工资/报销批次，扩展 `general` 类型纳入已审批通用付款单 |
| 历史兼容 | 创建默认资金账户并尽量回填旧流水/旧资金分录；无法确定账户的历史数据进入“待归集”列表，不猜测归属 |
| 全局月份 | 新增 React `BusinessMonthContext`；页面默认使用全局月份，年度台账和自定义区间页面保持独立 |

## 3. 目标业务流程

```text
资金账户/往来单位/操作人
          ↓
收付款单、借款单、报销单
          ↓  submit / approve / reject（追加审批事件）
已审批付款单 ──→ 付款批次 ──→ 标记付款 ──→ 自动凭证资金分录
收款单/现金单 ─────────────────→ 结算 ─────→ 自动凭证资金分录
          ↓
银行流水导入（指定资金账户）
          ↓
银行流水 ↔ 资金分录多对多核销
          ↓
银行/现金日记账、余额调节表、月结检查、财务报表
```

## 4. 数据模型

### 4.1 `fund_accounts` 资金账户

| 字段 | 说明 |
|---|---|
| `id` INTEGER PK | |
| `account_code` TEXT UNIQUE | 业务编码，如 `BANK-001` |
| `name` TEXT NOT NULL | 基本户、现金库、微信商户等 |
| `account_type` TEXT | `bank` / `cash` / `third_party` |
| `bank_name` / `account_no` | 银行类信息；账号默认脱敏展示 |
| `currency` TEXT DEFAULT `CNY` | 本期只允许 CNY，字段为后续预留 |
| `gl_account_code` TEXT NOT NULL | 对应 1001/1002/1012 等总账科目 |
| `opening_date` / `opening_balance` | 账户级启用日与期初余额 |
| `is_default` / `is_active` | 默认付款账户、停用状态 |
| `remark` / 时间戳 | |

约束：同一类型最多一个默认账户；存在已结算分录、已导入流水或未完成付款批次时不可删除，只允许停用。

### 4.2 `business_partners` 往来单位

支持 `supplier` / `customer` / `other` 三类；员工继续引用 `employees`，避免重复维护。

字段包括编码、名称、统一社会信用代码、联系人、电话、开户行、账号、默认会计科目、状态、备注。名称+税号去重；被业务单引用后只允许停用。

### 4.3 `operator_profiles` 本地操作人

字段：`id`、姓名、岗位角色（`requester` / `approver` / `cashier` / `admin`）、是否启用、备注、时间戳。

- 当前操作人保存在内存 State，并将最近一次选择写入 `app_settings.active_operator_id`。
- 应用解锁后若无有效操作人，进入业务页前要求选择。
- 安全事件仍记录 `security`；普通业务日志统一取当前操作人姓名。
- 本表不保存账号密码，不构成真正 RBAC；未来多用户化时可保持 `operator_id` 历史引用。

### 4.4 `fund_documents` 通用资金单据

核心字段：

- `document_no`：唯一编号，按类型和日期生成。
- `document_type`：`receipt` / `payment` / `transfer` / `advance` / `advance_settlement` / `reversal`。
- `belong_month`、`document_date`、金额、摘要、部门、费用类型、备注。
- `partner_id` 或 `employee_id`，二者按单据类型择一。
- `source_account_id` / `target_account_id`：付款取 source、收款取 target、转账两者都需且不得相同。
- `counter_account_code`：资金科目对方科目；付款/收款结算前必填。
- `status`：`draft` / `submitted` / `approved` / `rejected` / `batched` / `settled` / `void` / `reversed`。
- `payment_batch_id`、`reversal_of_id`、提交/审批/结算操作人与时间戳。

金额统一为正数，方向由 `document_type` 决定。任何更新都须执行 `ensure_month_open`；已月结月份只读。

### 4.5 `approval_events` 审批事件

追加式事件表：`entity_type`、`entity_id`、`action`、`from_status`、`to_status`、`operator_id`、`comment`、`created_at`。

- 不允许 UPDATE/DELETE。
- 报销单和资金单共用。
- approve/reject/void/reverse 必须填写意见或原因。
- 查询详情时按时间升序返回完整轨迹。

### 4.6 `business_attachments` 业务附件

通用附件表：实体类型、实体 ID、原文件名、归档路径、加密标志、大小、上传人、时间戳。

- 文件归档至 `app_data_dir/attachments/{entity_type}/{belong_month}/`。
- 复用现有 DEK/AES-GCM 方案加密；预览使用临时解密文件。
- 备份、恢复、数据体检和旧资料迁移必须覆盖 `attachments/`。

### 4.7 凭证与资金辅助核算

`voucher_lines` 增加 `fund_account_id INTEGER NULL REFERENCES fund_accounts(id)`。

新增 `vouchers.source_type='fund_document'`。因现有 SQLite CHECK 约束包含固定枚举，迁移必须在事务中重建 `vouchers` 表并保留原 ID、索引和外键关系；不得使用关闭外键后无校验覆盖。

生成规则：

- 收款：借目标资金账户总账科目，贷对方科目。
- 付款：借对方科目，贷来源资金账户总账科目。
- 内部转账：借目标账户科目，贷来源账户科目；两行分别带对应 `fund_account_id`。
- 员工借款：借其他应收款，贷来源资金账户。
- 借款核销：按报销抵扣、现金归还或工资扣回生成对应分录；不得重复核销。
- 冲正：复制原凭证并交换借贷方向，新凭证引用冲正单，原凭证不删除。

工资/报销付款凭证、银行流水手工凭证也必须在资金行写入 `fund_account_id`。

### 4.8 `bank_transactions` 扩展

新增 `fund_account_id`，未来导入必须指定 bank/third_party 账户；查询和唯一索引加入账户维度，避免不同银行同日同金额流水误判重复。

旧流水迁移：

- 只有一个有效银行账户时自动回填。
- 多账户且无法判断时保持 NULL，显示“待归集”，禁止参与自动对账。

### 4.9 `bank_reconciliation_allocations` 多对多核销

| 字段 | 说明 |
|---|---|
| `transaction_id` | 银行流水 |
| `voucher_line_id` | 带资金账户辅助核算的账面分录 |
| `allocated_amount` | 本次核销金额，正数 |
| `status` | `active` / `cancelled` |
| `match_method` | `auto` / `manual` / `migrated` |
| `score` / `remark` / 操作人 / 时间戳 | |

校验：账户相同、方向相符；流水累计分配不得超过收入/支出额；分录累计分配不得超过借/贷发生额；所有写入在事务中完成。

现有 `bank_transaction_matches` 在迁移后只读保留一个版本周期。能唯一定位付款凭证资金行的旧匹配迁入 allocation；不能定位的列入迁移报告，不静默丢失。

### 4.10 `bank_reconciliation_periods` 银行余额调节

字段：账户、月份、对账单期初/期末余额、账面期末余额、未达账项金额、调节后余额、状态（draft/confirmed）、确认人和时间。

确认条件：期初衔接、调节后余额差小于 0.005、无待归集流水。正式月结时，启用“严格对账”配置的银行账户必须完成当月确认。

### 4.11 员工借款核销关系

`advance_settlement_links` 连接借款资金单和核销来源：报销单、归还收款单、工资扣款记录或其他核销单。累计核销不得超过借款金额；输出未核销余额和账龄。

## 5. 状态机与职责边界

### 5.1 资金单据

```text
draft → submitted → approved → batched → settled
          ↓            ↓
       rejected      void（仅未结算）
          ↓
        draft

settled → reversal document → reversed
```

- 草稿可编辑；submitted 后业务字段冻结。
- approved 后不得直接改金额、账户、对方科目。
- payment/advance 可进入付款批次；receipt/transfer 可直接结算。
- settled 只能冲正，禁止直接删除/作废凭证。

### 5.2 报销单治理改造

- 移除新增/编辑弹窗中的审批状态和付款状态编辑。
- 移除报销列表“直接付款”入口；付款只能通过付款批次完成。
- submit/approve/reject 使用统一 approval_events。
- 可选经办复核开启时，审批人与提交人不得相同。
- 已审批后修改附件或发票必须先反审批，并记录原因、作废原计提凭证。

### 5.3 付款批次

- `batch_type` 增加 `general`，`payment_items.source_type` 增加 `fund_document`。
- 创建批次时必须选择付款资金账户；批次内所有项目使用同一账户。
- 导出后方可付款；付款后生成资金辅助凭证并将来源单据置 settled。
- 已付款批次不可作废；错误通过冲正单处理。

## 6. 日记账与对账口径

### 6.1 账面日记账

按资金账户查询 active 凭证分录，输出日期、凭证号、来源单号、摘要、对方单位、收入、支出、余额、对账状态。余额计算从账户期初开始，按日期、凭证号、分录顺序稳定排序。

### 6.2 银行流水账

展示银行原始流水、已核销金额、未核销金额、匹配分录。支持自动匹配候选预览后确认，不允许自动过程直接写入低置信匹配。

### 6.3 自动匹配评分

硬条件：同资金账户、方向一致、日期在配置窗口内、双方有未核销余额。

评分因素：金额完全一致、单号/批次号、对方户名、账号尾号、摘要关键词、日期距离。高分可一键确认，中低分只列候选。

## 7. 全局月份与导航

新增 `BusinessMonthContext`：

- 顶部月份变更后，仪表盘、考勤、OCR、工资、发票、报销、付款、流水、凭证、报表、月结等页面同步。
- 页面可临时切换月份时同时更新全局值，不维护第二份本地状态。
- 期初余额、科目余额表区间、社保年度、个税年度等特殊选择保持页面独立。
- 最近月份保存在 localStorage；不写数据库，不影响账务口径。

菜单新增“资金出纳”分组：资金账户、收付款单、付款批次、银行对账、资金日记账、借款备用金。原“薪酬核算”仅保留工资计算和社保台账。

## 8. 月结、分析、导出和安全联动

月结新增检查：

- 待审批资金单（阻塞）。
- 已审批未付款/未结算资金单（阻塞）。
- 已付款但无有效资金辅助凭证（阻塞）。
- 严格对账账户未确认余额调节表（阻塞）。
- 待归集银行流水（阻塞）。
- 部分核销流水/资金分录（warning，严格模式可配置阻塞）。
- 员工借款逾期（warning）。

导出：现金日记账、银行存款日记账、余额调节表、通用付款批次、员工借款余额与账龄。

安全：账户号码、往来单位账号、资金金额默认脱敏；附件加密；敏感导出与账户明文查看复用全局敏感解锁窗口。

## 9. 历史兼容与迁移策略

1. 所有 DDL 和回填在单事务内完成；升级前数据安全中心建议备份，迁移失败回滚。
2. 创建默认银行账户/现金账户时由迁移向导让用户确认名称、账号、期初，不在数据库初始化中伪造真实账号。
3. 旧付款批次增加可空 `fund_account_id`；首次打开资金账户页进入归集向导，未归集批次保持可查询但不可参与新对账。
4. 旧银行匹配可转换时写入 allocation，并保留 legacy ID 到 remark；不可转换项生成清单。
5. 旧凭证仅在资金科目能唯一映射账户时回填 `voucher_lines.fund_account_id`；否则保持 NULL。
6. 迁移完成前，新月结检查显示 warning；用户确认启用严格资金对账后转为 blocking。

## 11. 测试与验收

自动测试重点：

- DDL 升级和失败回滚、旧凭证/旧匹配迁移。
- 每类资金单状态机、职责分离、月结保护、冲正。
- 资金账户辅助分录和日记账滚动余额。
- 多对多核销的超额、方向、跨账户、取消、部分核销。
- 付款批次 general 类型及来源单据同步。
- 借款多次核销、超额拦截、账龄。
- 月结检查、Excel 导出、附件备份恢复和加密预览。
- 全局月份联动的前端单测或最小交互测试。

回归门槛沿用项目现有命令；每一批次必须同时运行针对性 Rust 测试和 `npx tsc --noEmit`，批次收尾运行完整 lint/build/cargo test。

Windows 手工验收覆盖：旧库升级、账户归集、收付款审批、付款批次、流水导入、多对多核销、日记账余额、月结阻塞、冲正、加密附件和导出文件打开。

## 13. 实施批次

- Gate 0：第六阶段 Windows 验收、备份恢复演练、基线冻结。
- 7A 基础底座：全局月份、资金账户、往来单位、操作人、附件底座。
- 7B 业务单据：通用收付款、审批事件、付款批次 general、自动凭证与冲正。
- 7C 资金对账：流水账户化、凭证分录辅助核算、多对多核销、日记账、余额调节表。
- 7D 管理闭环：借款备用金、报销治理、月结/仪表盘/导出/安全联动、全量回归。

每批均可独立发布，但 7B 不应早于资金账户和操作人底座，7D 的严格月结检查只能在历史归集向导完成后启用。
